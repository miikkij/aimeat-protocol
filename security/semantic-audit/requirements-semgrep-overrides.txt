# Versions forced over what Semgrep itself asks for, read by the compile line in
# requirements-semgrep.in through --override. Each line says why, and goes when Semgrep's own pin
# moves past it.
#
# semgrep 1.178.0 pins pyjwt~=2.13.0, and every 2.13.x carries the advisories fixed in 2.15.0
# (Dependabot #49, #70-#78, #84, #85, #88). The taint job never signs in to Semgrep and never
# verifies a token, so the newer minor release is safe for what it runs. An override replaces the
# whole requirement, so the [crypto] extra Semgrep asks for is repeated here.
pyjwt[crypto]>=2.15.0
#
# semgrep 1.178.0 (and 1.181.0, the newest on 2026-10-16) pins mcp==1.29.0, and every mcp before
# 1.30.0 carries GHSA-84m7-p3x7-pcfv (moderate: the StreamableHTTP server transport keeps sessions
# without a bound). The taint job runs `semgrep scan` and never starts Semgrep's MCP server, so the
# newer minor release is safe for what it runs. Kept below 2, which is a new major line.
mcp>=1.30.0,<2
#
# semgrep 1.178.0 pins the OpenTelemetry family at ~=1.37.0 (and ~=0.58b0 for the instrumentation
# packages), and every opentelemetry-api up to 1.45.0 parses a W3C tracestate header without a bound
# (GHSA-xcq7-p3pf-p88h, moderate; Dependabot #202). The sdk, the exporter and the instrumentation
# require their own api version exactly, so the whole family moves together. Kept below 2.
opentelemetry-api>=1.45.1,<2
opentelemetry-sdk>=1.45.1,<2
opentelemetry-exporter-otlp-proto-http>=1.45.1,<2
opentelemetry-instrumentation-requests>=0.66b1
opentelemetry-instrumentation-threading>=0.66b1
