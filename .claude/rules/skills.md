## Changing a skill that has an eval suite

- **Measure before and after, and report the delta.** A skill with a suite under `.claude/evals/<skill>/` is changed with `pnpm eval:skill <skill> --model <model> --max-cost-usd <ceiling>` run on the version before the change and again after it. The report says the model, the runs per case, the with-skill and without-skill scores, and the delta per case. One run proves nothing: on 2026-09-13 two identical headless runs of one task cost $0.27 and $0.72, and the eval runs each case three times in both arms for that reason.
- **The gate asks, the developer decides.** `pnpm check:skill-evals` (in `pnpm gate` and CI) fails when a skill with a suite, or its suite, changed since the last decision in `aimeat/security/skill-evals.json`, and prints the eval command with its cost ceiling. The eval costs money, so ask the developer first, then record `--ran "<scores>"` or `--skip "<reason; who decided>"`. Never record a skip on your own (Jouni, 2026-09-28).
- **Read the baseline for what it is.** An eval run loads no CLAUDE.md, rules or other skills, so the without-skill arm is a bare Claude. A delta of zero on a case means that model already does the thing unaided, which is a reason to write a harder case, not a reason to delete the skill. Measured on the first `aimeat-writing` suite: Sonnet gained +0.08, +0.08 and +0.33 on its three cases; Opus gained 0, 0 and +0.33, the gain on both being the administrator help line.
- **A suite is written like a test.** Each case gets graders on the answer and one `tool_used: Skill` indicator. Prefer `regex` graders (free, stable); keep `llm` graders to short answers with PASS and FAIL conditions, and pass `--judge-model opus` when the rubric needs judgement a small model does not have, such as whether Finnish reads as translated (every model run in this project is Opus, ruled 2026-09-18; this line said sonnet until then). A grader that has never failed in any run has not been shown to work: before trusting it, make it fail once on purpose. In the first `aimeat-writing` suite, five of the twelve scored graders failed at least once (the em-dash check in two cases, the kept STARTTLS term, two rubrics) and seven never failed in 36 runs, so those seven are guards against rarer tells that nothing has yet exercised.
- **A suite can measure a node skill too.** A folder under `.claude/evals/` with no skill folder of the same name beside it evaluates a built-in node skill, whose one home is its `skillMd` in `aimeat/src/data/builtin-skills*.ts` (today `aimeat-ai-capabilities`). It runs with `pnpm eval:skill --node-skill <name>`, and the gate digests the `skillMd` string. For a project skill the gate digests `SKILL.md`, every `references/*-rules.md` and the suite, and not the other reference files: a new row of reference data is not a change to the instructions, but a rule is, and the eval reads it. So instructions that live outside `SKILL.md` go in a file named `*-rules.md`, as `aimeat-writing/references/language-rules.md` does, never inside a data table's file.
- **One home for the skill.** The runner (`scripts/eval-skill.mjs`) builds a throwaway plugin from `.claude/skills/<skill>/` for every run. Do not add a plugin manifest to a skill folder or copy a skill under a plugin directory to evaluate it: the first changes how every session loads the skill, the second is a copy that drifts.
- **The same suite measures Codex.** `pnpm eval:skill <skill> --codex` (or `--node-skill <name> --codex`) runs the cases through `codex exec`, with the skill and without it, scored by the same graders; an `llm` grader is judged by a separate Codex run, and the `tool_used: Skill` indicator counts a shell read of the skill's `SKILL.md`. Each eval gets a temporary Codex home with a copy of the sign-in and the person's own skills, plugins and `AGENTS.md` left out, so the without-arm is a bare Codex. It runs on the ChatGPT plan Codex is signed in to, not on a dollar budget, so it takes no `--max-cost-usd`; `--dry-run` prints how many Codex calls a run makes. Ask before a run, as for the Claude arm, and record both arms' scores in the decision's note (written 2026-11-26).
