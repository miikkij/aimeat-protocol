## Identity in code

**Ask the caller object.** `callerOf(req, config.nodeId, storage)` (`src/middleware/caller.ts`) on a route and the session's `caller()` in an MCP tool group give one `CallerContext` (`src/services/caller-context.ts`), built once: `principal` (resolveIdentity), `owner`/`ownerGhii`, `kind`, `inPerson`, `visitor`, `scopes`, `has(word)` (requireScope's answer) and `operator()`, with the `auth` and `principalView` shapes services take. A caller built by hand, a literal role and an inline role or wildcard test are counted per file by `pnpm check:single-entry` and only go down (secaudit 2026-10, C9).

**Every route that stores or retrieves by identity uses `resolveIdentity(req.auth!, config.nodeId)`** from `src/utils/gaii.ts`, never raw `req.auth!.sub`. Owner sessions turn the bare name into a GHII; agent and ecosystem sessions return `sub` as-is. Skip it and owner data is stored under bare `alice`, invisible to list, search and update. Compare ownership against the resolved identity.

**A session from another node is a visitor, decided where the token is read.** `verifyJWT()` gives it role `federated` and its home GHII (`alice@home-node`) as `sub` and `owner`, so no endpoint can take it for the local account sharing its local part. Ask `isForeignPrincipal(auth)`, never `auth.federated` inline; shorten an identity to an account name with `localAccountName()` (a lookup) or `localAccountOf()` (a decision), never `split('@')[0]`, which turns a visitor back into the local namesake; `pnpm check:identity-shortening` refuses a new cut. Ruled 2026-09-24 after the September audit found the endpoint-by-endpoint fixes and the four gates still leaving endpoints that decided on the role or the name alone. → `docs/coding-guidelines/identity-model.md`

**The three principals and the account layer** (moved from CLAUDE.md on 2026-11-15; the worked patterns are in `docs/coding-guidelines/identity-model.md`). A GHII (`alice@node-id`) is a person and owns everything: the morsel balance, the profile, the trust. A GAII (`claude#alice@node-id`) is an AI agent with scoped permissions and its own trust score; it connects by device authorization (RFC 8628), where the owner approves it and picks the scopes, or the system creates it for a purpose the owner set up; an agent may approve another agent of the same owner, and the owner sees and can remove every agent. A GEAI (`eco:drum-news#alice@node-id`) is an ecosystem app, onboarded hello, approve, token with TOFU key pinning plus a scope and data-area allowlist, writing into its own `eco:` namespace and consented like an agent (`docs/building-an-aimeat-compatible-ecosystem-app.md`). A bare owner name (`alice`) is the account layer: `req.auth!.sub` for owner JWTs, `req.auth!.owner` for every principal. Hosted apps carry identity through scoped app grants that resolve `role:'app'` to the owner but are limited to the approved scopes. Morsels have one balance, `GHIIRecord.morselBalance`; agent and ecosystem balances are always 0, and `debit`/`credit` resolve any principal to the owner GHII, because the pace belongs to the human in whose name the agent acts.

Key files: `src/utils/gaii.ts`, `src/routes/ghii.ts`, `src/routes/agents.ts`, `src/auth/middleware.ts`, `src/routes/libs.ts`.

## Gates for this area

- **A security fix is looked up and recorded in the Security register.** Organism AIMEAT SECURITY (`ec7a728f-ad61-4b05-b6f0-e5bf9b47c16c`), workspace `ws-mvkjtfqtfgn` on aimeat.io holds every audit, finding, fix, exception and dependency or CVE change, whichever account or machine did the work. Before a fix, look the finding, file or rule up there (app tool `security_lookup` of `tietoturvakartta.html`, owner `happydude500001`); after it, update the finding with `finding_set` (`fixCommits` and the two proofs: the attack is refused, the designed use still works) and record the commit with `change_add`. Skill `user:happydude500001/tietoturvakartta` has the fields; the map is https://tietoturvakartta.apps.aimeat.io/ (2026-10-23, after three accounts' audits sat on three disks).
- **The owner sees everything their own agents hold.** A person's agents and apps act in their name, in their account, on permissions they granted and can pull, so a file or a record one of them stored is that person's own and `authorizeRead` lets the owner GHII read it. ONE DIRECTION, and the asymmetry is the point: an agent reading its OWNER's private data still goes through the ordinary visibility and consent checks, because a scoped agent must not ride the human's ownership. Ruled 2026-09-08, after an exact-identity match had hidden a person's own attachment from them and answered 403 on a file their own agent had sent in their name.
- **Six rules the August 2026 audit had to be written to discover.** Full text and the evidence for each: `docs/coding-guidelines/security-development-dna.md` invariants 11 to 16.
  - **The owner name is not a principal.** `req.auth!.owner` carries the human's name on app grants, ecosystem apps, agent JWTs and PATs alike, so `owner !== name` refuses a different PERSON and admits everything acting in this person's name. Naming the principal is the check. A change to the account itself goes behind `requireOwnerPrincipal()`, and `requireRole('owner')` is not that test.
  - **A role is granted, never inherited at mint time.** One mint copied the owner's roles onto the agent's token, and two calls then turned a scope-limited agent into an unscoped operator credential. When you add a mint, diff its role list against the other mints.
  - **A gate reads the normalized value, never the raw request.** A webhook allowlist read `body.source.type` while the builder defaulted a missing type to the same value, so omitting the field skipped the gate and built the record it would have refused. Same shape as an origin marker taken from a request header.
  - **Refuse before you write.** Three defects, one shape: bytes written before the name was claimed, a paywall standing down before comparing the coordinate, a response sent before the work it announced. Read the ORDER, not just the presence of the check.
  - **A permission word is enforced on every endpoint or it does not exist.** `organism:write` deletes the tool from an agent's MCP surface and is bypassed on the HTTP route, so an owner was told they controlled something they did not.
  - **Deprecated is not removed.** Deprecating names the flag, the default and the removal version. Three Tier 0.5 write paths were marked deprecated in the RFC, behind no flag, and stayed live on every node until they were deleted on 2026-08-23.
- **A list that admits never takes a right away, and a caller of a shared rule passes its refusal through.** An agent whose owner is an active member acts with the owner's rights whether or not it is on an organism's agent list; the list only adds what it was made for. A gate that reads list membership before the caller's own standing and returns early is this defect: on 2026-11-10 listing the creator's agent under agentAccess "all" took its workspace writes away (`services/organism/namespace-access.ts`, `attachedAsParticipant`). A route or tool that asks a shared rule returns that rule's status, code and reason; it rewrites only wording that names something internal, and keeps the code. The draft write had replaced the real refusal with "Request access", sending the agent to ask for its own workspace. The tell is a refusal built as a literal string right after a call that returned a reason, or a client working around a server rule instead of the rule being fixed (moved from `docs/pitfalls.md` §129 on 2026-11-21).
- **A credential that is not a node session is declared, not verified in the handler.** A data space participant, an outside party, an app party, a UCP platform, an intake visitor's token, an EU wallet's session, a federation peer's signed message and a package seller's or claimant's signed request are kinds in `src/auth/credential-kinds.ts`; a route names its kind with `acceptCredential('<kind>', …)` from `src/auth/credential-strategies.ts` (another node's kinds in `credential-strategies-node.ts`) and reads the principal with `credentialOf(req, kind)`. A new kind is a strategy there, built from its one verifier. A federation peer's signature is verified unconditionally: no option skips it. `check:open-writes` takes a route off its list when its strategy refuses a missing credential; its list only shrinks; `check:federation-signatures` counts a route that declares a signature strategy as peer-signed (codebase analysis 2026-11-03, item B8; decision 2 of 2026-11-05).
- **Security**, on any change to `src/routes/`, `src/auth/`, `src/services/`, `src/storage/`, federation, extensions or an AI path: authorize against `resolveIdentity(req.auth!, …)` and never a client-supplied id; keep server-trusted config and secrets out of principal-writable namespaces; route non-constant outbound HTTP through `safeFetch`; gate every mutation with `requireScope`/`requireRole`; verify federation Ed25519 signatures unconditionally. Anything whose safe value differs between localhost and the public internet goes in `.env.example` with a safe public default and a documented local override. Identity-touching features ship with cross-owner and cross-scope "→403" tests. → `docs/coding-guidelines/security-development-dna.md`
