# Pixel Mirage

Source for the **Pixel Mirage** app on aimeat.io: a dither studio for people, and the same renderer
sold to agents as a priced app-tool. This is app DNA, not node core (see
`docs/coding-guidelines/architecture.md` and the core-vs-apps boundary); nothing here is imported by
`aimeat/src`.

## What is live, and which file it came from

| Live on aimeat.io | Built from | Deployed by |
|---|---|---|
| App `pixel-mirage.html` at <https://pixel-mirage.apps.aimeat.io/> | `dist/pixel-mirage.html` | `aimeat_app_publish` (presigned PUT) |
| Extension `pixel-mirage` v1.0.0, actions `dither` / `variants` / `styles` | `dist/*.js` + `dist/manifest.yaml` | `node deploy-ext.mjs` |
| Skill `node:pixel-mirage` | `SKILL.md` (verbatim) | `aimeat_skill_publish` |
| EXCHANGE offerings `dither` + `variants`, 1 morsel each | the app-tool manifest, see below | `aimeat_app_tools_publish` |

`dist/` is generated and committed on purpose: it is the exact artefact that was published, so
`git log dist/pixel-mirage.html` is the history of what users actually got. Regenerate it with
`node build.mjs` and it will come out byte-identical from the same sources.

The app-tool manifest (prices, schemas, ODPS descriptor, `exchange: true`) lives in node storage as
the public memory record `apps.pixel-mirage.html.tools` under the owner's GHII, not in this repo.
Read it with `aimeat_app_tools_get`; it is the source of truth for the marketplace listing.

## Layout

```
SKILL.md              the published skill, verbatim
src/
  engine.js           THE dither engine: palettes, algorithms, adjustments, geometry
  codec.js            pure-JS PNG + baseline JPEG codec (needed only in the sandbox)
  app.template.html   the studio; build.mjs inlines engine.js at /*__ENGINE__*/
  manifest.yaml       extension manifest (metadata / limits / actions / schemas)
  actions/            the action bodies; build.mjs prepends codec + engine + common
dist/                 what was published (generated)
test/                 node test harnesses, see below
build.mjs             src/ -> dist/
deploy-ext.mjs        PUT dist/ to /v1/extensions/pixel-mirage and activate
```

**`engine.js` is deliberately shared.** The studio inlines it and every extension action bundles it,
so a preview a person tunes in the browser and a render an agent buys are the same picture. Change
the engine and you change both; that is the point. The sandbox has no module system, which is why
each action carries its own copy rather than importing one.

## Tests

```bash
node test/codec.test.mjs                  # PNG/JPEG decode against PIL-generated fixtures
node test/engine.test.mjs <photo>         # every palette and algorithm renders
node test/action.test.mjs <photo.jpg>     # the BUILT bundles, run the way the sandbox runs them
node test/live.mjs                        # drives the DEPLOYED extension, reports real timings
```

`test/codec.test.mjs` needs fixtures generated by PIL (see the fixture-writing snippet in the test
file header) and `test/live.mjs` needs an owner token in `.token`; both are gitignored.

## The constraint everything is shaped by

A sandboxed extension action gets **5 s of QuickJS and 64 MB**, roughly 20x slower than Node. Hence:

- `ctx.fetch` returns decoded TEXT, so an extension can never fetch binary. Images arrive as base64
  in the input, or through `ctx.memory.getPublic` on a public record.
- Output is capped at 768 px, input at 3 MB of base64, and a PNG source at 0.9 MP. A PNG must be
  inflated whole; a JPEG decodes at 1/2, 1/4 or 1/8 scale, so a large source should be a JPEG.
- The action **prices a recipe before rendering it** (`assertAffordable` in `src/actions/common.js`)
  and refuses with a concrete smaller size rather than timing out. The per-pixel costs in `COST_US`
  are measured on this node; re-measure with `test/live.mjs` if the node's limits change.
